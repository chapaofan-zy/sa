# 活动排序

---

## 活动排序概述

活动排序是根据项目活动之间的逻辑关系，确定活动的先后顺序，建立项目活动之间的逻辑网络关系。

活动排序主要回答以下问题：

- 哪些活动必须先做；
- 哪些活动可以并行开展；
- 一个活动完成或开始到什么程度后，另一个活动才能开始或完成。

活动排序关注的是活动之间的逻辑关系，不是确定活动的持续时间，也不是安排具体人员。

---

## 依赖关系的分类

依赖关系可以从两个维度进行理解：

- 按依赖的性质或来源分类：强制性依赖关系、可自由处理的依赖关系、外部依赖关系；
- 按活动的时间逻辑分类：平行关系、顺序关系、搭接关系。

这两个分类维度可以组合使用，并不是完全互斥的分类。

### 按依赖性质或来源分类

#### 强制性依赖关系

强制性依赖关系也称硬逻辑关系或必要依赖关系，是由于技术、物理、法律、合同或业务要求而形成的必然依赖关系。

例如：

```text
数据库设计 → 数据库开发
```

通常需要先完成数据库设计，才能进行数据库开发。强制性依赖关系通常不能随意改变。

#### 可自由处理的依赖关系

可自由处理的依赖关系也称选择性依赖关系、软逻辑关系或优先逻辑关系，是项目团队根据经验、行业惯例或最佳实践人为确定的活动顺序。

例如，团队通常先进行概要设计，再进行详细设计，但该顺序并不一定是技术上的绝对要求，可以根据项目实际情况进行调整。

可自由处理的依赖关系如果被取消或改变，可能会增加项目风险，但通常不是不可改变的硬约束。

#### 外部依赖关系

外部依赖关系是指项目活动依赖项目外部的活动、组织、供应商、政府机构或其他因素。

例如：

```text
供应商交付服务器 → 项目组安装服务器
```

其他例子包括等待政府审批、客户确认需求、第三方接口开放或外部测试机构出具报告。项目团队通常只能协调外部依赖，不能完全控制其完成时间。

### 按活动时间逻辑分类

#### 平行关系

平行关系是指两个或多个活动之间没有严格的先后约束，可以同时进行。

例如，需求分析完成后，界面设计和数据库设计可以同时开展：

```text
             ┌──> 界面设计
需求分析 ────┤
             └──> 数据库设计
```

平行关系可以缩短项目总工期，但仍需要确认活动之间不存在资源冲突或其他隐藏依赖。

#### 顺序关系

顺序关系是指一个活动必须在另一个活动之后进行，前后活动通常不能同时开展。

例如：

```text
需求分析 → 系统设计 → 编码 → 测试
```

在网络图中，顺序关系通常使用完成—开始（FS）关系表示，即前一个活动完成后，后一个活动才能开始。

#### 搭接关系

搭接关系也称重叠关系或交叉关系，是指后一个活动在前一个活动尚未完全结束时已经开始，两个活动的执行时间存在重叠。

例如，编码尚未全部完成时，测试人员已经开始测试已经完成的模块。

搭接关系可以压缩项目总工期，但会增加沟通、协调和返工风险。搭接关系通常可以使用开始—开始（SS）、完成—完成（FF）或完成—开始（FS）加提前量来表示。

## 活动逻辑关系

### 完成—开始（FS）

前一个活动完成后，后一个活动才能开始。

```text
活动A完成 → 活动B开始
```

示例：需求分析完成后，才能开始系统设计。

FS 是最常见的活动逻辑关系。

### 开始—开始（SS）

前一个活动开始后，后一个活动才能开始。

```text
活动A开始 → 活动B开始
```

示例：开发工作开始后，测试用例编写即可开始。

### 完成—完成（FF）

前一个活动完成后，后一个活动才能完成。

```text
活动A完成 → 活动B完成
```

示例：系统测试完成前，测试报告编写不能完成。

### 开始—完成（SF）

前一个活动开始后，后一个活动才能完成。

```text
活动A开始 → 活动B完成
```

示例：新系统开始运行后，旧系统才能停止运行。

SF 关系较少使用。

## PDM：前导图法

PDM（Precedence Diagramming Method）也称：

- 单代号网络图；
- 节点活动法；
- AON（Activity on Node）。

### 表示方式

- 节点表示活动；
- 箭线表示活动之间的逻辑关系。

```text
[需求分析] ──FS──> [系统设计] ──FS──> [编码]
```

### 特点

- 活动写在节点中；
- 箭线表示依赖关系；
- 可以表示 FS、SS、FF、SF 四种逻辑关系；
- 通常不需要使用虚活动；
- 现代项目管理软件中使用较多。

---

## ADM：箭线图法

ADM（Arrow Diagramming Method）也称：

- 双代号网络图；
- 箭线活动法；
- AOA（Activity on Arrow）。

### 表示方式

- 箭线表示活动；
- 节点表示事件或里程碑。

```text
(1) ──需求分析──> (2) ──系统设计──> (3) ──编码──> (4)
```

### 特点

- 活动写在箭线上；
- 节点表示活动的开始或完成事件；
- 主要表示完成—开始（FS）关系；
- 可能需要使用虚活动；
- 在现代项目管理中使用相对较少。

### 虚活动

虚活动主要用于 ADM 中，用来准确表示活动之间的逻辑依赖。

虚活动具有以下特点：

- 工期为 0；
- 不消耗资源；
- 只用于表示逻辑关系；
- 通常使用虚线表示。

---

## PDM 与 ADM 的对比

| 对比项 | PDM | ADM |
|---|---|---|
| 中文名称 | 前导图法 | 箭线图法 |
| 其他名称 | 单代号网络图、节点活动法 | 双代号网络图、箭线活动法 |
| 英文表示 | AON | AOA |
| 活动表示 | 节点表示活动 | 箭线表示活动 |
| 节点表示 | 活动 | 事件或里程碑 |
| 箭线表示 | 依赖关系 | 活动 |
| 支持的关系 | FS、SS、FF、SF | 主要是 FS |
| 虚活动 | 通常不需要 | 可能需要 |
| 使用情况 | 现代项目管理中更常用 | 传统方法，使用相对较少 |

核心区别：

> PDM：节点是活动，箭线是关系；
> ADM：箭线是活动，节点是事件。

## 提前量与滞后量

### 提前量

提前量（Lead）允许后续活动提前开始，使前后活动的执行时间产生重叠。

例如：

```text
A ──FS，提前2天──> B
```

表示 A 尚未完成时，B 可以提前 2 天开始。

### 滞后量

滞后量（Lag）是后续活动需要等待一段时间后才能开始或完成的时间间隔。

例如：

```text
A ──FS，滞后3天──> B
```

表示 A 完成后还需要等待 3 天，B 才能开始。

提前量和滞后量是逻辑关系中的时间调整，不是活动本身的持续时间，也不是浮动时间。

## 依赖关系组合示例

例如：等待供应商交付硬件后，项目组才能安装硬件。该关系可以同时描述为：

- 外部依赖关系：供应商属于项目外部；
- 强制性依赖关系：没有硬件就无法安装；
- 顺序关系：交付完成后才能安装；
- FS 关系：供应商交付完成，安装活动开始。

又如，编码完成一部分后，测试人员就开始测试，可以描述为：

- 项目团队内部的依赖关系；
- 可能属于可自由处理的依赖关系；
- 属于搭接关系；
- 可以使用 SS 或 FS 加提前量表示。

## 记忆要点

- 强制性依赖：技术、法律或物理上必须如此；
- 可自由处理的依赖：团队根据经验或习惯确定，可以调整；
- 外部依赖：依赖项目外部主体或事件；
- 平行关系：多个活动可以同时进行；
- 顺序关系：完成一个活动后再进行另一个活动；
- 搭接关系：前一个活动未完成，后一个活动已经开始；
- PDM：点上写活动，节点是活动；
- ADM：箭上写活动，箭线是活动；
- ADM 可能需要虚活动；
- PDM 可以表示 FS、SS、FF、SF 四种关系；
- FS 是最常见的逻辑关系。

---

## 易错点

1. 活动排序不等于活动持续时间估算。活动排序确定的是逻辑顺序，不是计算活动需要多少时间。
2. 活动不一定全部串行，没有直接依赖关系的活动可以并行开展。
3. 平行关系、顺序关系和搭接关系是对活动时间安排的概括；FS、SS、FF、SF 是 PDM 中更精确的逻辑关系表示。
4. PDM 中节点表示活动，ADM 中箭线表示活动，不要混淆。
5. 虚活动工期为 0、不占用资源，主要用于 ADM 中表达逻辑依赖。
6. 提前量和滞后量不是活动持续时间，也不是浮动时间。
