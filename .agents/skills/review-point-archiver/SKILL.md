# 复习要点归档

## 目标

只整理当前对话中有依据的复习内容，并将确认后的 Markdown 笔记保存到项目根目录的 `第二关/`。不使用外部资料补充结论，不修改其他学习资料目录。

## 工作流程

### 1. 提取内容

- 提取当前对话中的知识点、概念关系、题目与解析、易错点、记忆方法和待验证内容。
- 排除闲聊和与复习无关的内容；没有可归档内容时不要创建文件。
- 对不确定、矛盾或缺少依据的内容标记为“待验证”，不要自行补全。

### 2. 确定归档位置

- 归档根目录固定为项目根目录下的 `第二关/`。
- 目标文件允许使用两种形式：`第二关/<知识点>.md` 或 `第二关/<主题>/<知识点>.md`；主题层级不是必需项。
- 用户明确给出目标路径时优先遵循用户指定；用户没有指定时，先检查 `第二关/` 中已有的目录和文件，保持相邻归档内容的组织方式。
- 主题具有明确分类价值或已有对应主题目录时使用主题子目录；主题不必要、无法稳定判断或只是为了凑层级时，直接将文件放在 `第二关/` 根目录。
- 相同主题或知识点优先追加到已有文件，避免创建重复文件。
- 主题或知识点无法准确判断时，列出候选路径并标记为“待确认”，不要自行选择。
- 文件名使用简洁的知识点名称，避免使用路径分隔符、控制字符或无法稳定复用的临时标题。

### 3. 写入前确认

在任何新建目录、创建文件或修改文件之前，展示以下归档方案并等待用户确认：

```markdown
## 归档方案

- 主题：<如适用则填写主题；不适用则填写“无”>
- 知识点：<本次归档的知识点>
- 目标文件：`<第二关/下的目标文件路径>`
- 文件操作：<新建 / 追加 / 拆分>
- 内容摘要：<只概括当前对话中已有的信息>
- 待验证或待确认：<如无则填写“无”>

请确认知识点和归档路径后再写入文件。
```

用户提出修改时，更新方案并再次确认。用户未确认时，不执行任何归档写入。

### 4. 归档内容

确认后再创建所需目录，并新建或追加 Markdown 文件。新文件按以下结构组织，只保留实际有内容的章节：

```markdown
# <主题或知识点>

## 复习要点

- <当前对话中确认的要点>

## 题目与解析

<当前对话中出现的题目、选项和解析；没有则省略>

## 易错点

- <当前对话中明确提到的易错点；没有则省略>

## 待验证

- <尚未确认的内容；没有则省略>
```

- 有主题时使用主题作为一级标题；没有主题时使用知识点名称作为一级标题。
- 追加时放入已有的对应标题下；没有合适标题时再添加最小必要标题。
- 只写入当前对话可追溯的信息，保留题干、选项、答案和解析中的不确定部分。
- 发现已有相同内容时不重复追加；不要覆盖已有笔记中的其他内容。
- 不在本 skill 中修改 README、现有专用 skill 或 `第二关/` 之外的资料。

### 5. 验证结果

归档后检查目标文件存在、目录和文件名正确、原有内容未被覆盖、没有重复追加，并报告：

```text
归档完成。

文件：<已创建或追加的文件>
主题：<整理的主题>
待验证内容：<如无则填写“无”>
```

## 触发示例

- “保存这段复习要点。”
- “把刚才的知识点归档到第二关。”
- “整理本次对话，形成复习笔记。”

未出现明确保存、整理、记录或归档意图时，不主动写入 `第二关/`。
