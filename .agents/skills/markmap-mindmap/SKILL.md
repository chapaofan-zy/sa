# Markmap 思维导图

## 目标

将用户指定的 Markdown 内容提炼成适合 Markmap 展示的简洁层级结构，并生成两个文件：

- `<章节名>.md`：提炼后的 Markdown 源文件
- `<章节名>-思维导图.html`：由 Markmap 生成的可浏览思维导图

以输入文档为唯一事实来源；不得补写、推测或改变原文事实。

## 执行流程

### 1. 解析输入

- 支持单个 Markdown 文件、目录，或用户明确列出的多个 Markdown 文件。
- 用户给出相对路径时，以当前工作目录解析；先确认路径存在且类型正确。
- 单个文件：默认将输出放在该文件所在目录。
- 单个目录：默认将输出放在该目录根目录。
- 多个文件：默认将输出放在这些文件的共同父目录；若用户指定输出目录，优先使用用户指定目录。
- 如果输入范围或输出位置无法从请求中合理确定，先询问用户，不要擅自猜测。

### 2. 推测章节名和输出文件名

根据输入范围确定一个稳定的 `章节名`，并将输出文件命名为：

```text
<输出目录>/<章节名>.md
<输出目录>/<章节名>-思维导图.html
```

按以下优先级推测章节名：

1. 用户明确指定的章节名或输出文件名（去掉 `.md`、`.markdown`、`.html` 扩展名）。
2. 单个目录输入：使用该目录的最后一级目录名。
3. 单个文件输入：使用该文件所在目录的最后一级目录名。
4. 多个文件输入：使用所有文件的共同父目录的最后一级目录名。
5. 以上名称属于通用目录名（例如 `docs`、`doc`、`markdown`、`知识库`、`资料`）或无法取得时，向上查找最近的非通用目录名；仍无法确定时，使用 `章节` 并在最终报告中说明。

处理章节名时遵循以下规则：

- 保留中文、英文、数字、空格、短横线和下划线，去除首尾空白。
- 将路径分隔符、换行符和文件名非法字符替换为短横线，并合并连续短横线。
- 不生成以 `.` 开头的隐藏文件名，不使用 `.` 或 `..`。
- 章节名为空时使用 `章节`。
- 不因章节名包含空格而擅自改用 `summary` 等固定名称。

### 3. 检查工具

先检查 `markmap-cli` 是否可用：

```bash
command -v markmap
markmap --version
```

如果命令不存在或无法执行：

- 停止后续生成步骤。
- 告知用户需要自行安装 `markmap-cli`。
- 不自动执行 `npm`、`pnpm` 或其他安装命令。

### 4. 收集 Markdown 文件

- 对目录递归收集扩展名为 `.md` 或 `.markdown` 的普通文件。
- 对用户明确列出的文件，按用户给出的顺序处理并去重。
- 对目录收集的文件，按照逻辑排序，保证多次生成结果顺序一致。
- 默认跳过以下生成物、依赖目录和版本控制目录：
    - 本次推测出的 `<章节名>.md` 和 `<章节名>-思维导图.html`
    - `.git/`、`node_modules/`、`dist/`、`build/`、`coverage/`
    - `.venv/`、`venv/`、`__pycache__/`
- 隐藏目录默认不递归进入；用户明确指定的隐藏文件或目录除外。
- 忽略二进制文件、符号链接指向的目录以及非 Markdown 文件。
- 没有找到可读 Markdown 文件时，停止并明确说明原因。

### 5. 读取和整理内容

按确定的文件顺序读取完整内容，然后生成面向思维导图的精简汇总 Markdown：

- 以原文标题为主要整理内容，尽量保留能够体现主题结构、知识脉络和重点内容的标题；次要、重复或对思维导图帮助不大的标题可以跳过。
- 每个来源文档的标题节点必须使用 Markdown 链接，链接到对应的源 `.md` 文件；链接路径以生成的 HTML 所在目录为基准，使用可用的相对路径。
- 仅对极少数最重要的标题补充一到两句话概括，优先保留原文明确说明的定义、核心观点、关键步骤、重要区别、结论或限制条件；普通标题不得展开正文。
- 不保留大段原文正文、完整列表、表格、引用、图片引用或代码块，也不要把汇总 Markdown 写成原文摘录。
- 以文件名或相对路径作为每份文档的来源标题；多个文件时，为每个来源建立独立分支，避免内容混在一起。来源标题也可以在内容过少或不利于阅读时省略，但不得造成不同文档内容混淆。
- 删除重复目录、生成时间、构建标记、无意义空白等机械元数据，以及不影响理解主题结构的细节。
- 不补写、推测或改变原文事实；对冲突内容不自行裁决，保留能够体现冲突的简短表述，并通过来源标题区分。
- 如果文档没有标题，使用不改变事实的文件名作为该文档标题。
- 第一行一级标题必须设为实际的 `章节名`；其余标题层级应连续、适合 Markmap 解析。不要为了追求视觉效果凭空添加知识点或结论。

推荐的精简汇总结构如下：

```markdown
# 章节名

## [核心主题 A](相对路径/来源文档.md)

- 仅在该主题特别重要时，用一到两句话概括原文明确内容。

## [核心主题 B](相对路径/来源文档.md)
```

### 6. 写入输出文件

- 确保输出目录存在；只在用户允许的工作区内写入。
- 将提炼后的汇总内容写入输出目录下的 `<章节名>.md`。
- 将 `<章节名>-思维导图.html` 视为配套生成文件。
- 如果同名 Markdown 或 HTML 已存在：
    - 只有确认它们是本流程之前生成的输出文件时才允许覆盖。
    - 无法确认来源时停止并报告文件冲突，不得覆盖用户文件。
- 写入前检查汇总内容非空，并至少包含一个一级标题。
- 生成输出文件时，不要把输出 Markdown 或 HTML 再次作为输入收集。

### 7. 生成 HTML

在输出目录中执行：

```bash
markmap <章节名>.md -o <章节名>-思维导图.html
```

实际执行时，将 `<章节名>` 替换为已经清理后的文件名，不要把尖括号作为命令参数的一部分。

生成前确认汇总 Markdown 中的标题链接满足以下要求：

- 链接目标是对应的源 `.md` 文件，而不是汇总 Markdown 或 HTML 文件。
- 链接使用相对于输出 HTML 文件所在目录的路径；路径中的空格或特殊字符应按 Markdown 链接语法正确转义或编码。
- 标题文本放在链接文本中，例如 `## [主题标题](../原文/主题.md)`，使 Markmap 中显示的标题本身可点击。
- 对于无法通过相对路径访问的源文件，不要伪造链接；报告该文件的链接无法生成。

如需定位错误，先确认当前目录是输出目录，再检查输入文件是否可读、标题是否闭合、链接括号是否完整、代码围栏是否完整。不要通过删除内容来掩盖生成错误。

### 8. 验证结果

生成后确认：

- `<章节名>.md` 存在且大小大于 0。
- `<章节名>-思维导图.html` 存在且大小大于 0。
- HTML 文件包含基本 HTML 内容，而不是错误日志或空文件。
- 汇总 Markdown 仅包含标题和极少数一到两句话的重点概括。
- 汇总 Markdown 中的源文档标题均使用相对 Markdown 链接；抽查生成的 HTML，确认标题链接被保留且目标路径正确。
- 最终报告使用实际生成的章节名和绝对路径，不再使用固定的汇总文件名。

验证失败时，报告失败的具体步骤、命令输出和已成功生成的文件；不要声称任务完成。

## 异常处理

- 输入路径不存在：报告具体路径并停止。
- 输入路径不是文件或目录：报告类型问题并停止。
- 目录为空或没有 Markdown 文件：报告扫描范围和原因并停止。
- 文件无法读取：报告具体文件；除非用户要求忽略，否则停止，避免生成不完整汇总。
- 章节名无法可靠推测：先询问用户，不要擅自使用与内容无关的名称。
- 输出文件冲突：报告具体冲突路径，并等待用户指定覆盖或改名策略。
- `markmap` 执行失败：保留已生成的 Markdown，报告命令和错误信息，不编造 HTML 已成功生成。
- 任何阶段都不得凭空补全文档内容、猜测文件含义或静默忽略错误。

## 最终报告

成功时报告：

1. 推测或采用的章节名，以及命名依据。
2. 实际处理的 Markdown 文件数量及路径范围。
3. 汇总 Markdown 的绝对路径。
4. Markmap HTML（`<章节名>-思维导图.html`）的绝对路径。
5. 如有跳过的文件或内容清理，简要说明原因。

失败时报告：

1. 失败发生的步骤。
2. 具体原因和相关命令输出。
3. 已生成且可继续使用的文件路径。
4. 用户需要采取的下一步操作。
