# 06-企业信息化知识点摘要

## 06-01 企业信息化概述

| 关键词 | 一句话概括 |
| --- | --- |
| 企业信息化 | 以流程优化为基础，利用信息技术提升信息共享和经营效益。 |
| 业务流程重组 | 重新设计组织结构和工作方法，使业务适应市场与信息社会。 |
| 核心业务应用 | 优先用技术解决最影响经营结果的核心业务问题。 |
| 信息系统建设 | 建设系统以支持企业生产经营活动。 |
| 主题数据库 | 面向稳定业务主题组织数据，为多个应用共享数据基础。 |
| 资源管理方法 | 统一管理人、财、物和信息资源，提高资源配置效率。 |
| 五种建设视角 | 可概括为改业务、抓重点、建系统、管数据、管资源。 |

## 06-02 信息资源管理

| 关键词 | 一句话概括 |
| --- | --- |
| IRM 目标 | 畅通内外部信息流，提升信息资源利用率、企业效益和竞争力。 |
| 数据资源管理 | 重点控制数据维护、数据安全、数据规划和数据标准。 |
| 信息处理管理 | 关注管理人员获取和处理信息的流程与方法。 |
| IRM 组织 | 需明确管理方向和控制方式，建立指导委员会及组织机构。 |
| 信息资源目录 | 建立信息资源目录是信息资源分类的起点和基础。 |
| 管理维度 | 可沿用业务部门分类，也可由综合部门建立管理分类。 |
| 信息来源维度 | 按提供部门设置类目，分类赋值工作量较小。 |
| 应用主题维度 | 按服务目标和应用主题分类，同一信息可能归入多个主题。 |
| 数据元素 | 数据元素是最小且不可再分的信息单位。 |
| 信息分类编码 | 按信息属性或特征分类编码，是最基础的信息资源标准。 |
| 用户视图 | 数据元素的集合，是用户看到的实体及系统输入输出媒介。 |
| 概念数据库 | 综合概括最终用户对数据存储的看法和信息需求。 |
| 逻辑数据库 | 将概念数据库细化为规范化基本表，是系统设计基础。 |
| 标准实施 | 标准应逐步建立、切实可行并保留灵活性，一致性尤为重要。 |
| IRP 定义 | 全面规划信息的产生、获取、处理、存储、传输和利用。 |
| IRP 七步骤 | 定义职能域，分析业务和数据，建标准、模型及关联矩阵。 |
| 业务主线 | 从职能域到业务过程、业务活动，再复查确认业务模型。 |
| 数据主线 | 采集分析用户视图，建立数据标准、基本表和主题数据库。 |
| 分散存储 | 数据分布在不同位置，通常更贴近各地业务。 |
| 集中存储 | 数据集中保存，便于统一管理。 |
| 分布式数据库 | 连接多个分散数据库单元，形成逻辑统一的数据库。 |
| IRM、IRP与资源网 | IRM管资源，IRP做规划，信息资源网承载数据与系统互联。 |

## 06-03 企业信息化规划

| 关键词 | 一句话概括 |
| --- | --- |
| 信息化规划 | 融合企业战略、管理、流程重组和技术的业务管理技术规划。 |
| 规划层次 | 企业战略定方向，信息系统支撑业务，IT落实技术，IRP统一数据。 |
| 战略一致性 | 信息化战略应与企业战略一致，并转化为系统战略目标。 |
| 初级阶段 | 业务部门提需求，IT部门按需求分别实施。 |
| 中级阶段 | 企业先改进流程和组织，再由IT部门分别实施需求。 |
| 高级阶段 | 企业统一制定信息化战略，整体规划、分步实施。 |
| BITA | 以业务为导向，贯通战略、组织、流程、IT管理和过渡计划。 |
| EITA | 从战略出发建立IT原则、规范、模式和标准，指导投资决策。 |
| ISSP | 从企业战略出发统一规划信息架构和内外部信息资源。 |
| ISSP 三阶段 | 依次以数据处理、内部管理系统、集成和战略需求为重点。 |
| BSP | 全面调查信息需求，制定支持企业长短期需求的总体方案。 |
| CSF | 找出影响系统成功的关键因素，确定信息需求和开发优先级。 |
| CSF 分类 | 分为内部、外部、监控型和建设型四类关键成功因素。 |
| SST | 将企业战略集合转化为信息系统战略集合并反复评审。 |
| SDP | 先建稳定的主题数据库，再围绕它开发应用系统。 |
| IE | 以BSP和SDP为基础，使信息系统开发过程工程化。 |
| SG | 用2×2矩阵按现有依赖和未来影响分析系统组合。 |
| SG 四类 | 规划条件分为战略型、转变型、工厂型和支持型。 |
| VCA | 分析输入、处理、输出活动，识别增值或减值的关键环节。 |
| SAM | 检查企业战略与信息基础架构是否保持一致。 |

## 06-04 企业信息系统

### 企业资源规划（ERP）

| 关键词 | 一句话概括 |
| --- | --- |
| ERP 定义 | 在信息技术基础上集成企业资源，支持统一管理、决策和运营。 |
| ERP 管理思想 | 以内部供应链为基础，连接供应商、采购、生产、销售和客户。 |
| ERP 软件产品 | 作为管理思想的载体，随应用深入向更高层次发展。 |
| ERP 管理系统 | 集成企业部门、资源和运行环境的信息系统。 |
| ERP 作用 | 协调资源、共享信息，提升市场响应并降低经营风险。 |
| ERP 功能 | 覆盖财会、物流、生产控制和人力资源管理。 |
| 二次开发 | 在套装软件上扩展修改，投资较少、周期较短。 |
| 定制开发 | 按个性化需求重开发，周期长、投资大且实施风险较高。 |
| ERP与CRM | ERP偏内部资源协同，CRM偏客户关系管理，二者需要配合。 |
| MRPI | 待确认：原文暂保留“MRPI”这一罗马数字写法。 |

### 客户关系管理（CRM）

| 关键词 | 一句话概括 |
| --- | --- |
| CRM 定义 | 以客户为重要资产和关怀中心，建立长期有效关系并增加利润。 |
| 客户价值 | 分为既成价值、潜在价值和模型价值，并实施一对一营销。 |
| 客户服务 | 直接影响忠诚客户的形成与保留，是CRM关键内容。 |
| 市场营销 | 管理商机和商业活动，帮助潜客转化并保持忠诚度。 |
| 客户资料库 | 连接市场营销与客户服务，形成共享客户信息资源。 |
| CRM 分析 | 分析客户信息以判断客户价值并提升客户价值。 |
| 触发中心 | 通过多种渠道与客户沟通，触发客户与CRM交互。 |
| 挖掘中心 | 分析客户、交流和沟通信息，为个性化服务提供依据。 |
| CRM 实施要素 | 需要畅通交流渠道、有效分析信息并与ERP良好集成。 |

### 供应链管理（SCM）

| 关键词 | 一句话概括 |
| --- | --- |
| 供应链 | 由供应商、制造商、仓库、配送中心和渠道商构成物流网络。 |
| SCM 定义 | 集成管理从供应商到最终用户的物流计划和控制。 |
| SCM 五项内容 | 依次包括计划、采购、制造、配送和退货。 |
| 配送网络重构 | 需求或外部条件变化时调整原有配送网络。 |
| 配送战略 | 包括直接转运、经典配送和直接运输战略。 |
| 供应链集成 | 协同供应链节点并建立合适的战略伙伴关系。 |
| 库存控制 | 综合渠道库存、订货量、需求预测和库存周转率管理。 |
| 产品设计 | 产品设计会影响供应链生产、配送和成本。 |
| SCM 技术支持 | 基础技术和生产支持系统共同支撑供应链决策。 |
| 顾客价值 | 衡量企业对顾客贡献大小的指标。 |
| ERP与SCM | ERP协同企业内部资源，SCM延伸到外部供应链节点。 |

### 产品数据管理（PDM）与产品生命周期管理（PLM）

| 关键词 | 一句话概括 |
| --- | --- |
| PDM 定义 | 管理所有与产品相关信息和过程的一门技术。 |
| 产品相关信息 | 包括零件、配置、文档、设计文件、产品结构和权限信息。 |
| 产品相关过程 | 包括过程定义和过程管理。 |
| PDM 作用 | 集成并跟踪产品数据、开发过程和使用者。 |
| PLM 生命周期 | 产品经历培育、成长、成熟、衰退和结束五个阶段。 |
| PLM 定义 | 集成人、过程和信息，协同管理产品全生命周期。 |
| PDM与PLM | PDM重产品数据和开发过程，PLM覆盖从概念到报废。 |

### 知识管理

| 关键词 | 一句话概括 |
| --- | --- |
| 知识管理 | 管理知识的识别、获取、存储、共享、评判、保护和转化。 |
| 显性知识 | 可用文字数字表达，常以资料、规范和手册等形式存在。 |
| 隐性知识 | 难以完整文字化，主要存在于个人经验、技巧和认知中。 |
| 知识生成工具 | 用于产生新想法、模式、流程或重组原有知识。 |
| 知识编码工具 | 用标准形式表达知识，便于共享和交流。 |
| 知识转移工具 | 促进知识在企业内部传播和分享。 |

### 企业门户（EP）

| 关键词 | 一句话概括 |
| --- | --- |
| EP 作用 | 优化业务模式、扩展渠道、改善服务并提升形象和凝聚力。 |
| 企业网站 | 偏向简单的信息单向发布，互动较少。 |
| EIP | 统一集成应用、数据和互联网资源，提供个性化入口。 |
| EKP | 面向员工提供消息、工作内容和所需知识。 |
| EAP | 集成企业业务流程，是企业信息系统的集成界面。 |
| EP 实施要点 | 关注单点登录、流程整合、个性化、应用集成和知识转化。 |

### 决策支持系统（DSS）

| 关键词 | 一句话概括 |
| --- | --- |
| DSS 定义 | 用数据、模型和知识辅助人进行半结构化或非结构化决策。 |
| DSS 定位 | DSS辅助决策，不能代替决策者。 |
| 结构化决策 | 规则和模型确定，可用算法生成并选择最优方案。 |
| 半结构化决策 | 可用算法生成方案，但通常只能选出较优方案。 |
| 非结构化决策 | 过程复杂，难以用确定模型描述，通常没有直接最优解。 |
| DSS 功能 | 提供决策信息，管理模型，分析预测数据并支持通信。 |
| 数据库子系统 | 存储维护决策数据，是模型库和推理部分的基础。 |
| 模型库子系统 | 构建管理模型，体现DSS的模型驱动特点。 |
| 推理部分 | 由知识库、管理系统和推理机构成，负责知识推理。 |
| 用户接口 | 提供DSS与用户交互的人机界面。 |
| DSS与BI | BI侧重形成分析结果，DSS进一步结合模型辅助选方案。 |

### 商业智能（BI）

| 关键词 | 一句话概括 |
| --- | --- |
| BI 定义 | 利用业务数据了解情况，支持管理和发展活动及时判断。 |
| 数据预处理 | 通过ETL把异构数据整理成可分析形式。 |
| 数据仓库 | 集中处理海量业务数据，为后续分析提供基础。 |
| 数据分析 | 用OLAP和数据挖掘等技术加工数据并发现规律。 |
| 数据展现 | 将分析结果以直观形式可视化呈现。 |

## 06-05 电子商务

| 关键词 | 一句话概括 |
| --- | --- |
| 电子商务 | 利用计算机、网络和通信技术实现商务过程电子化、数字化和网络化。 |
| B2C | 企业借助Internet直接开展在线销售。 |
| B2B | 有业务联系的企业通过网络形成虚拟企业圈。 |
| C2C | 平台为消费者买卖双方提供在线交易场所。 |
| 其他模式 | 包括B2G、C2B和C2G等衍生或非主流模式。 |
| 用户接口标准 | 规定用户界面、图像和对话设计原则。 |
| 基本功能标准 | 涵盖交易、支付、安全、签名鉴别和记录保留。 |
| 数据编码标准 | 规定组织机构、商品等对象及报文语义的定义编码。 |
| 电子商务标准 | 包括数据交换、识别卡、通信网络及其他相关标准。 |
| 普遍性 | 电子商务覆盖行业、地域、形式和社会范围。 |
| 方便性 | 以较简捷方式完成过去复杂的商业活动。 |
| 整体性 | 将信息、支付、订单、物流和售后集成为整体。 |
| 安全性 | 保障传输、存储和交易安全，保护隐私并防止泄露。 |
| 协调性 | 使系统各部分和各业务环节协调配合。 |
| 电子商务优势 | 可降低营销成本、提高效率、扩大渠道和改善服务。 |
| 电子商务技术 | 主要包括网络通信、EDI、安全、支付和数据库技术。 |

## 06-07 企业应用集成（EAI）

| 关键词 | 一句话概括 |
| --- | --- |
| EAI 定义 | 连接多个企业系统，消除信息孤岛并实现整体协同。 |
| 表示集成 | 集中多个系统界面，属于较浅的黑盒集成。 |
| 数据集成 | 直接围绕数据集成，灵活但受业务逻辑变化影响。 |
| 控制集成 | 在业务逻辑层集成应用，集成点位于程序代码中。 |
| 业务流程集成 | 用标准数据和统一工作流管理跨系统业务信息交换。 |
| 企业间应用集成 | 让客户和伙伴共享供应链中的应用和数据库。 |
| EDA 定义 | 用事件触发消息，在独立低耦合模块间传递信息。 |
| 异步 | 发送方发出消息后不必立即等待响应。 |
| 发布订阅 | 一个事件可被多个获授权的订阅系统接收。 |
| 解耦 | 发布者无需知道订阅者，订阅者也无需了解发布者细节。 |
| 异步消息机制 | 不要求接收者立即响应，但需考虑暂不可用情况。 |
| 事件管理 | 负责识别、定义和聚集事件。 |
| ESB | 面向服务体系的基础总线，各服务通过总线互访。 |
| 应用服务层 | 承载需要集成的应用系统和数据库。 |
| 总线接入层 | 通过适配器和协议支持应用接入ESB。 |
| 核心服务层 | 提供消息、队列、目录、数据转换和映射等服务。 |
| 业务支持层 | 用标准对象和服务模型定义可复用业务流程。 |
| 事件驱动EAI | 以适配器、ESB和统一消息服务实现应用间通信。 |

## 06-08 业务流程重组

| 关键词 | 一句话概括 |
| --- | --- |
| BPR 定义 | 根本再思考并彻底再设计流程，以获得可衡量的显著成效。 |
| BPR 四核心 | 核心内容是根本性、彻底性、显著性和流程。 |
| BPR 原则 | 以流程为中心，采用团队管理并以顾客为导向。 |
| 现有流程重设计 | 先研究描述现状，再重新设计业务流程。 |
| 理想流程设计 | 从零构建理想流程，过程中可参考其他企业。 |
| 战略规划 | 明确企业战略目标，认清企业发展方向。 |
| 流程规划 | 选择和分析核心流程，识别需改进流程并绘制新流程。 |
| 数据规划 | 识别流程产生、控制和使用的数据并分类。 |
| 功能规划 | 用数据类与过程的CU矩阵识别子系统和功能模块。 |
| 实施规划 | 确定开发顺序和项目计划，资源有限时优先关键系统。 |
| CU矩阵 | 待确认：原文未展开C和U的具体含义。 |
| BPR与普通信息化 | BPR先重思流程本身，普通建设可能只加快旧流程。 |
