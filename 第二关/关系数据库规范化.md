# 关系数据库规范化

## 复习要点

### 1. 整体案例

使用学生选课系统说明关系数据库中的主要概念。原始关系为：

```text
R(
  学号,
  学生名,
  系号,
  系名,
  课程号,
  课程名,
  教师号,
  教师名,
  成绩
)
```

示例数据：

| 学号 | 学生名 | 系号 | 系名 | 课程号 | 课程名 | 教师号 | 教师名 | 成绩 |
|---|---|---|---|---|---|---|---|---|
| S01 | 张三 | D01 | 计算机系 | C01 | 数据库 | T01 | 王老师 | 90 |
| S01 | 张三 | D01 | 计算机系 | C02 | 操作系统 | T02 | 李老师 | 85 |
| S02 | 李四 | D01 | 计算机系 | C01 | 数据库 | T01 | 王老师 | 88 |

关系中的函数依赖为：

```text
学号 → 学生名, 系号
系号 → 系名
课程号 → 课程名, 教师号
教师号 → 教师名
(学号, 课程号) → 成绩
```

这些依赖表示：

- 一个学号确定一个学生名和系号。
- 一个系号确定一个系名。
- 一个课程号确定一个课程名和教师号。
- 一个教师号确定一个教师名。
- 一个“学号 + 课程号”确定一条成绩。

### 2. 关系和冗余

关系模式可以理解为一张表的结构，例如：

```text
R(学号, 学生名, 系号, 系名, 课程号, 课程名, 教师号, 教师名, 成绩)
```

表中的列称为属性，具体的数据行构成关系实例。

原表中张三、计算机系、数据库、王老师等事实被重复保存，这属于数据冗余。冗余可能导致：

- 更新异常：教师改名时需要修改多行，漏改会产生不一致。
- 插入异常：没有学生选某门课时，可能无法单独录入课程信息。
- 删除异常：删除最后一条选课记录时，课程信息可能一并丢失。

冗余不等同于整行重复。真正需要消除的是同一个业务事实被无意义地重复保存。

### 3. 函数依赖

函数依赖写作：

```text
X → Y
```

表示只要两个元组的 X 值相同，它们的 Y 值就一定相同。

例如：

```text
学号 → 学生名
课程号 → 课程名, 教师号
```

但通常不成立：

```text
学号 → 课程号
```

因为一个学生可以选多门课。

示例中的 `课程号 → 教师号` 是业务建模假设，表示每门课程在该案例中固定对应一名教师；在其他业务中，一门课程可能由多名教师讲授，此依赖就不一定成立。

### 4. 候选码、主属性和非主属性

单独的 `学号` 不能唯一确定一条选课记录，单独的 `课程号` 也不能唯一确定一条记录，但 `(学号,课程号)` 可以：

```text
(学号, 课程号) → 学生名, 系号, 系名, 课程名, 教师号, 教师名, 成绩
```

因此候选码为：

```text
(学号, 课程号)
```

候选码中的属性 `学号` 和 `课程号` 是主属性；其他属性是非主属性。

### 5. Armstrong 公理和依赖推导公式

#### 自反律

如果 `Y` 是 `X` 的子集，则：

```text
Y ⊆ X  ⇒  X → Y
```

例如：

```text
(学号,课程号) → 学号
(学号,课程号) → 课程号
```

#### 增广律

如果：

```text
X → Y
```

则对任意属性集合 `Z`：

```text
XZ → YZ
```

例如由 `学号 → 学生名` 可以得到：

```text
(学号,课程号) → (学生名,课程号)
```

#### 传递律

如果：

```text
X → Y
Y → Z
```

则：

```text
X → Z
```

在本案例中：

```text
学号 → 系号
系号 → 系名
所以 学号 → 系名
```

同理：

```text
课程号 → 教师号
教师号 → 教师名
所以 课程号 → 教师名
```

#### 分解律

如果：

```text
X → YZ
```

则：

```text
X → Y
X → Z
```

例如：

```text
学号 → 学生名,系号
```

可以分解为：

```text
学号 → 学生名
学号 → 系号
```

#### 合并律

如果：

```text
X → Y
X → Z
```

则：

```text
X → YZ
```

例如：

```text
课程号 → 课程名
课程号 → 教师号
所以 课程号 → 课程名,教师号
```

#### 伪传递律

如果：

```text
X → Y
WY → Z
```

则：

```text
WX → Z
```

例如：

```text
学号 → 系号
(课程号,系号) → 系名
所以 (学号,课程号) → 系名
```

函数依赖集合 `F` 能够推出的全部函数依赖称为 `F+`。Armstrong 公理是函数依赖推导的基础。

### 6. 属性闭包

属性闭包 `X+` 表示从属性集合 `X` 出发，依据函数依赖能够推出的全部属性。

求 `学号+`：

```text
学号+ = {学号}
学号 → 学生名,系号，得到 {学号,学生名,系号}
系号 → 系名，得到 {学号,学生名,系号,系名}
```

所以 `学号+` 不能覆盖所有属性，`学号` 不是候选码。

求 `课程号+`：

```text
课程号+ = {课程号}
课程号 → 课程名,教师号，得到 {课程号,课程名,教师号}
教师号 → 教师名，得到 {课程号,课程名,教师号,教师名}
```

`课程号` 也不是候选码。

求 `(学号,课程号)+`：

```text
(学号,课程号)+ = {学号,课程号}
学号 → 学生名,系号，得到 学生名,系号
系号 → 系名，得到 系名
课程号 → 课程名,教师号，得到 课程名,教师号
教师号 → 教师名，得到 教师名
(学号,课程号) → 成绩，得到 成绩
```

最终得到原关系的全部属性，因此 `(学号,课程号)` 是超码。由于 `学号` 和 `课程号` 单独都不是超码，所以 `(学号,课程号)` 是候选码。

### 7. 第一范式 1NF

1NF 要求每个字段保存一个原子值。

反面例子：

| 学号 | 学生名 | 所选课程 |
|---|---|---|
| S01 | 张三 | 数据库、操作系统 |

一个单元格保存了多个课程，不满足 1NF。

正面做法是拆成多行：

| 学号 | 学生名 | 课程 |
|---|---|---|
| S01 | 张三 | 数据库 |
| S01 | 张三 | 操作系统 |

记忆：

```text
1NF：一个格子只能放一个值。
```

### 8. 第二范式 2NF

2NF 要求：在满足 1NF 的基础上，所有非主属性必须完全依赖候选码，不能只依赖联合候选码的一部分。

本案例的候选码是 `(学号,课程号)`，但有：

```text
学号 → 学生名,系号
课程号 → 课程名,教师号
```

`学生名、系号` 只依赖 `学号`，`课程名、教师号` 只依赖 `课程号`，它们只依赖联合候选码的一部分，属于部分依赖。因此原表满足 1NF，但不满足 2NF。

分解为：

```text
学生(学号, 学生名, 系号)
课程(课程号, 课程名, 教师号)
选课(学号, 课程号, 成绩)
```

分解后：

- 学生信息依赖于 `学号`。
- 课程信息依赖于 `课程号`。
- 成绩依赖于完整的 `(学号,课程号)`。

如果候选码只有一个属性，则不存在“只依赖候选码一部分”的问题，满足 1NF 后通常自动满足 2NF。

记忆：

```text
2NF：不能只依赖联合主键的一部分。
```

### 9. 第三范式 3NF

3NF 要求：在满足 2NF 的基础上，非主属性不能传递依赖候选码。

本案例中存在：

```text
学号 → 系号
系号 → 系名
所以 学号 → 系号 → 系名
```

系名 `系名` 通过系号 `系号` 间接依赖学号 `学号`，是传递依赖。

课程和教师之间也有：

```text
课程号 → 教师号
教师号 → 教师名
所以 课程号 → 教师号 → 教师名
```

因此还需要继续分解：

```text
学生(学号, 学生名, 系号)
系(系号, 系名)
课程(课程号, 课程名, 教师号)
教师(教师号, 教师名)
选课(学号, 课程号, 成绩)
```

最终各表中的非主属性直接依赖本表主码，不再通过其他非主属性间接依赖主码。

形式化地说，对于每个非平凡函数依赖 `X → A`，至少满足以下条件之一：

1. `X` 是超码；
2. `A` 是主属性。

入门记忆：

```text
3NF：不能通过另一个非主属性间接依赖主键。
```

### 10. 无损连接分解

分解后，如果将各子关系重新连接，能够准确恢复原关系，不产生伪元组，称为无损连接分解。

形式上，二元分解要求：

```text
r = πR1(r) ⋈ πR2(r)
```

对于两个关系，常用判断条件是：设公共属性为 `X = R1 ∩ R2`，如果能够推出：

```text
X → R1
```

或者：

```text
X → R2
```

则该二元分解是无损的。

本案例的最终分解中：

- `学号` 能确定学生信息。
- `系号` 能确定系信息。
- `课程号` 能确定课程信息。
- `教师号` 能确定教师信息。
- `(学号,课程号)` 能确定选课成绩。

因此连接：

```text
学生 ⋈ 系 ⋈ 选课 ⋈ 课程 ⋈ 教师
```

可以恢复原始选课信息，不会产生错误组合。

反面例子：将 `选课(学号,课程号,成绩)` 错误分解为：

```text
R1(学号,课程号)
R2(课程号,成绩)
```

原数据：

| 学号 | 课程号 | 成绩 |
|---|---|---|
| S01 | C01 | 90 |
| S02 | C01 | 80 |

投影为：

`R1(学号,课程号)`：

| 学号 | 课程号 |
|---|---|
| S01 | C01 |
| S02 | C01 |

`R2(课程号,成绩)`：

| 课程号 | 成绩 |
|---|---|
| C01 | 90 |
| C01 | 80 |

连接后会产生 `(S01,C01,80)` 和 `(S02,C01,90)` 等原来不存在的记录，因此是有损连接。

### 11. 保持依赖

保持依赖的意思是：关系分解之后，原来的函数依赖仍然可以只在各个子表中检查，不需要先把所有子表连接起来。

本案例的依赖对应关系如下：

| 原依赖 | 检查位置 |
|---|---|
| `学号 → 学生名,系号` | 学生表 |
| `系号 → 系名` | 系表 |
| `课程号 → 课程名,教师号` | 课程表 |
| `教师号 → 教师名` | 教师表 |
| `(学号,课程号) → 成绩` | 选课表 |

所以最终分解保持依赖。

反面例子：将原关系分解为：

```text
R1(学号,学生名,系号)
R2(学号,课程号,课程名,教师号,教师名,成绩)
```

如果某个原依赖的决定属性和被决定属性分散在不同子表中，就无法在单个子表内直接检查，可能需要连接后才能验证，这种情况不满足保持依赖。

无损连接和保持依赖关注的问题不同：

| 性质 | 关注点 |
|---|---|
| 无损连接 | 拆开后再连接，数据能否正确恢复 |
| 保持依赖 | 不连接表，所有依赖能否继续检查 |

一个分解可以无损但不保持依赖，也可以保持依赖但有损。理想情况是同时满足二者。

### 12. 三个范式的记忆

```text
1NF：字段值必须原子化。
2NF：不能只依赖联合主键的一部分。
3NF：不能通过另一个非主属性间接依赖主键。
```

## 易错点

- 冗余不只是整行重复，也包括同一个业务事实在多行中反复保存。
- 2NF 主要针对联合候选码；如果候选码只有一个属性，通常不会发生部分依赖。
- 3NF 不是简单地要求所有属性都不重复，而是消除非主属性对候选码的传递依赖。
- 只有某一组数据连接后没有产生伪元组，不能单独证明分解一定无损；无损性要求对所有满足函数依赖的数据都成立。
- 示例中的 `课程号 → 教师号` 依赖取决于业务规则，不是所有选课系统都成立。
- 外键字段在不同表中重复出现，可能是建立表间联系所必需的，不应简单地全部视为无意义冗余。
