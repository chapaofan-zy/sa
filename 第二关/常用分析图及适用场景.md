# 常用分析图及适用场景

## 复习要点

### 1. Gantt 甘特图

#### 样式

横向时间轴配合任务条。任务条表示任务的开始时间、结束时间和持续时间，也可以表示当前完成进度。

```text
任务       1月1日  1月5日  1月10日  1月15日
需求分析   █████
系统设计          ███████
编码                     █████████
测试                              █████
```

#### 适用场景

- 项目计划和排期
- 查看任务是否延期
- 安排多人或多团队工作
- 展示项目阶段进度和里程碑

#### 需要注意

甘特图强调“什么时候做、做多久、完成到什么程度”。当任务依赖关系复杂时，单看甘特图不够直观。

#### 关键词

时间轴、任务、开始时间、结束时间、持续时间、进度、排期、里程碑。

### 2. Fishbone 鱼骨图

#### 样式

中间是一条主骨，末端是要分析的问题或结果，分支骨刺表示可能的原因。

```text
人员 -----┐
方法 -----┤
设备 -----┤
材料 -----┼----> 项目延期
环境 -----┤
管理 -----┘
```

#### 适用场景

- 分析问题原因
- 质量管理和改进
- 故障复盘
- 组织头脑风暴

#### 需要注意

鱼骨图用于系统整理和分类可能原因，不能单独证明某个原因一定是真正根因。

#### 关键词

问题、结果、原因、主骨、骨刺、因果、人员、方法、设备、材料、环境、管理。

### 3. PERT 图

#### 样式

使用节点和箭头组成任务网络，箭头表示任务之间的依赖关系。

```text
[需求分析]
      | 3天
      v
[系统设计] --5天--> [编码]
      |                 |
      +--2天--> [原型] -+
                         v
                       [测试]
```

#### 适用场景

- 任务依赖关系复杂的项目
- 工期存在不确定性的项目
- 找出项目关键路径
- 判断哪些任务延期会影响整体交付

PERT 可以估算乐观时间、最可能时间和悲观时间，并据此计算预期工期：

```text
预期时间 = (乐观时间 + 4 * 最可能时间 + 悲观时间) / 6
```

#### 关键词

节点、任务、箭头、依赖关系、关键路径、乐观时间、最可能时间、悲观时间、预期时间、不确定性。

#### 与进度网络图的关系

进度网络图把项目活动及其先后依赖关系组织成网络，适合分析任务依赖、关键路径和延期影响。PERT 适用于工期存在不确定性的项目，常与进度网络图结合使用。

### 4. E-R 图

E-R 图是实体-联系图，用于描述数据库中有哪些数据，以及数据之间是什么关系。

#### 图形元素

- 实体：矩形，如“学生”“课程”
- 属性：椭圆，如“学号”“姓名”
- 联系：菱形或连线，如“选修”
- 基数：表示实体之间的数量关系，如 `1:1`、`1:N`、`M:N`

#### 示例

```text
[学生] N ---- 选修 ---- M [课程]
  |                         |
学号、姓名              课程号、课程名
```

表示一个学生可以选修多门课程，一门课程也可以被多个学生选修，因此是 `M:N` 关系。

#### 适用场景

- 数据库需求分析
- 设计表结构前梳理实体和关系
- 发现数据重复或遗漏
- 明确主键、外键和关联关系

#### 关键词

实体、属性、联系、矩形、椭圆、菱形、基数、`1:1`、`1:N`、`M:N`、主键、外键。

### 5. DFD 数据流图

DFD 用于描述数据从哪里来，经过哪些处理，存储在哪里，最后流向哪里。

#### 基本元素

- 外部实体：客户、银行、其他系统
- 处理过程：审核订单、计算金额
- 数据存储：订单库、客户档案
- 数据流：订单信息、审核结果、付款信息

#### 示例

```text
客户 -> 提交订单 -> 订单处理 -> 订单数据库
                         |
                         -> 生成支付信息 -> 支付平台
```

#### 适用场景

- 系统需求分析
- 功能分解
- 分析数据的输入、处理、存储和输出
- 梳理系统边界及各处理过程之间的数据交换

#### 需要注意

DFD 重点表示数据流动，不重点表示部门职责、业务办理顺序或项目工期。图中的箭头表示数据，不是业务步骤本身。

#### 关键词

外部实体、处理过程、数据存储、数据流、输入、处理、存储、输出。

### 6. 业务流程图

业务流程图描述一项业务如何办理，通常体现参与者、操作步骤、判断条件、单据以及部门之间的交接。

#### 示例

```text
员工提交申请
      |
部门负责人审批
   /       \
通过       不通过
 |           |
人事备案    返回修改
```

#### 适用场景

- 梳理现行业务
- 明确参与部门和岗位职责
- 分析业务步骤、判断条件和交接关系
- 发现流程瓶颈并进行流程优化
- 为系统需求分析提供业务依据

#### 需要注意

业务流程图重点表示“谁在什么条件下做什么事”。它可以包含数据或单据的流转，但关注重点是业务活动及其顺序，不是完整的数据存储和处理模型。

#### 关键词

参与者、部门、岗位、业务活动、顺序、判断、单据、交接、泳道。

### 7. 数据流与业务流程的区别

| 对比维度 | 数据流 | 业务流程 |
| --- | --- | --- |
| 关注对象 | 数据、信息、文件 | 业务活动、操作步骤、职责 |
| 典型表达 | 订单信息、付款结果、发货通知 | 提交订单、审核订单、安排发货 |
| 关注问题 | 数据从哪里来、到哪里去、如何被处理 | 谁在什么条件下按什么步骤完成业务 |
| 主要图形 | 数据流图（DFD） | 业务流程图、泳道图 |

例如“客户购买商品”的业务流程是“客户下单 -> 销售审核 -> 仓库发货 -> 财务开票”；对应的数据流包括订单信息、审核结果、出库通知和发票信息。

## 快速选择

```text
安排项目时间和完成进度       -> Gantt
分析问题的可能原因           -> Fishbone
分析任务依赖和关键路径       -> PERT / 进度网络图
设计数据库中的数据关系       -> E-R
分析系统中的数据处理和流向   -> DFD
梳理业务步骤和参与者职责     -> 业务流程图
```

## 对比记忆

- Gantt：看日历排期。
- PERT / 进度网络图：看任务依赖、关键路径和延期影响。
- Fishbone：从结果反推可能原因。
- E-R：描述实体、属性以及实体之间的联系。
- DFD：描述数据如何流动和处理。
- 业务流程图：描述谁按什么步骤完成业务。
- 数据流与业务流程：数据流是“传什么”，业务流程是“做什么”。
