# 软件工具分类

---

## 一、软件工具分类概述

软件工具通常按照其服务的软件生命周期阶段和对象，分为：

1. 软件开发工具；
2. 软件维护工具；
3. 软件管理和支持工具。

三类工具并不是绝对隔离的，有些工具可以跨多个类别使用，具体分类取决于工具在实际场景中的用途。

---

## 二、软件开发工具

### 2.1 定义

软件开发工具是辅助完成软件需求分析、设计、编码、测试和发布等开发活动的工具，主要用于提高开发效率、保证软件质量和减少重复劳动。

### 2.2 主要类型

| 类型 | 作用 | 示例 |
|---|---|---|
| 需求分析工具 | 编写、管理和跟踪需求 | Jira、禅道、Confluence、IBM DOORS |
| 建模工具 | 绘制流程图、用例图、类图、时序图等 | Enterprise Architect、StarUML、Visio、PlantUML |
| 界面设计工具 | 设计原型和用户界面 | Figma、Axure、Sketch、Adobe XD |
| 编程工具 | 编写和调试源代码 | Visual Studio Code、IntelliJ IDEA、Visual Studio、Eclipse |
| 编译工具 | 将源代码转换为可执行程序 | GCC、Clang、Javac、TypeScript Compiler |
| 构建工具 | 自动完成编译、打包和依赖处理 | Maven、Gradle、Make、CMake、Webpack、Vite |
| 版本控制工具 | 管理源代码版本和变更 | Git、SVN、Mercurial |
| 测试工具 | 执行单元测试、接口测试、性能测试等 | JUnit、pytest、Postman、JMeter、Selenium |
| 持续集成工具 | 自动构建、测试和发布 | Jenkins、GitLab CI、GitHub Actions |
| 数据库开发工具 | 设计数据库、编写和调试 SQL | MySQL Workbench、DBeaver、Navicat、DataGrip |
| 代码质量工具 | 检查代码规范、缺陷和安全问题 | SonarQube、ESLint、Checkstyle、Pylint |

### 2.3 示例

开发电商系统时，可以使用 Figma 设计页面原型，使用 StarUML 绘制系统模型，使用 IntelliJ IDEA 编写 Java 代码，使用 Maven 管理项目构建，使用 Git 管理代码版本，使用 JUnit 编写单元测试，使用 Jenkins 自动构建和发布。这些都属于软件开发工具的应用。

---

## 三、软件维护工具

### 3.1 定义

软件维护工具是支持软件交付后进行修改、修复、改进和适应环境变化的工具。

### 3.2 软件维护类型

- **改正性维护**：修复软件缺陷；
- **适应性维护**：适应操作系统、数据库、硬件等环境变化；
- **完善性维护**：增加功能、改善性能；
- **预防性维护**：提高可维护性，预防未来问题。

### 3.3 主要类型

| 类型 | 作用 | 示例 |
|---|---|---|
| 缺陷跟踪工具 | 记录、分派和跟踪 Bug | Jira、禅道、Bugzilla、Redmine |
| 版本控制工具 | 比较历史版本、回滚和合并代码 | Git、SVN |
| 代码阅读与导航工具 | 快速理解大型程序结构 | IDE、Source Insight、Understand |
| 代码分析工具 | 分析复杂度、依赖关系和潜在缺陷 | SonarQube、Coverity、PMD |
| 调试工具 | 定位程序运行错误 | GDB、LLDB、IDE 调试器 |
| 性能分析工具 | 找出 CPU、内存、数据库等性能瓶颈 | JProfiler、VisualVM、YourKit |
| 日志分析工具 | 查找运行异常和故障原因 | ELK、Graylog、Splunk |
| 运行监控工具 | 监控系统状态、资源和服务可用性 | Prometheus、Grafana、Zabbix |
| 数据库迁移工具 | 管理数据库结构和数据变更 | Flyway、Liquibase |
| 重构工具 | 在不改变外部功能的情况下改善代码结构 | IntelliJ IDEA、Visual Studio、Rider |
| 逆向工程工具 | 从程序或数据库中恢复结构信息 | Enterprise Architect、Doxygen、反编译工具 |

### 3.4 示例

系统上线后出现“用户无法支付”的问题时，可以通过 Jira 或禅道登记缺陷，通过日志平台查找错误日志，使用调试工具定位代码，使用 Git 查看最近修改，修改代码并补充测试，再使用 Jenkins 自动构建和部署，最后使用监控工具观察修复效果。这个过程主要使用软件维护工具。

### 3.5 与开发工具的区别

- 软件开发工具关注：**如何构建一个新系统**；
- 软件维护工具关注：**如何理解、修改、修复和改进已有系统**。

Git、IDE、测试工具和持续集成工具既可以用于开发，也可以用于维护。

## 四、软件管理和支持工具

### 4.1 定义

软件管理和支持工具不是直接用于编写程序，而是用于支持软件项目的计划、组织、协作、配置、质量、风险和过程管理。

其主要使用者包括项目经理、产品经理、配置管理员、测试管理人员、质量保证人员、运维人员和开发团队。

### 4.2 主要类型

| 类型 | 作用 | 示例 |
|---|---|---|
| 项目管理工具 | 制定计划、分配任务、跟踪进度 | Jira、禅道、Microsoft Project、Trello |
| 任务协作工具 | 管理待办事项和团队协作 | Asana、飞书、Trello、Notion |
| 配置管理工具 | 管理代码、文档、构建配置和发布版本 | Git、GitLab、SVN、Nexus |
| 需求管理工具 | 需求编写、评审、追踪和变更管理 | DOORS、Jama、Jira、禅道 |
| 文档管理工具 | 编写、存储和共享项目文档 | Confluence、语雀、Notion、GitBook |
| 质量管理工具 | 质量检查、审计、度量和评估 | SonarQube、TestRail、质量管理平台 |
| 风险管理工具 | 识别、分析和跟踪项目风险 | Jira、Excel、项目管理平台 |
| 成本和资源管理工具 | 管理预算、人员、设备和工时 | Microsoft Project、ERP、工时管理系统 |
| 测试管理工具 | 管理测试计划、用例、缺陷和测试报告 | TestRail、禅道、qTest |
| 发布管理工具 | 管理版本发布、审批和部署过程 | Jenkins、GitLab、Argo CD、Spinnaker |
| 沟通工具 | 支持团队沟通和信息共享 | 企业微信、钉钉、飞书、Slack、Teams |
| 软件过程改进工具 | 支持过程度量、评估和改进 | CMMI 支持平台、度量分析平台 |
| 资产和许可证管理工具 | 管理软件、硬件、许可证和配置项 | ServiceNow、GLPI、CMDB 系统 |

### 4.3 示例

软件项目需要制定进度计划、分配开发和测试任务、管理项目文档、记录项目风险、跟踪需求变更、统计开发工时、管理软件版本和进行质量审计。这些工作主要使用软件管理和支持工具。

## 五、三类工具对比

| 分类 | 主要服务对象 | 主要目标 | 典型问题 |
|---|---|---|---|
| 软件开发工具 | 开发人员、测试人员 | 建设软件系统 | 如何设计、编码、测试和构建软件？ |
| 软件维护工具 | 维护人员、开发人员、运维人员 | 修改和保障已有系统 | 如何定位缺陷、修改代码和监控运行状态？ |
| 软件管理和支持工具 | 项目经理、管理人员、质量人员、全体团队 | 管理软件项目和开发过程 | 如何安排计划、控制质量、管理风险和协同工作？ |

## 六、常见工具的分类辨析

### 6.1 Git

Git 主要属于：

- 软件开发工具中的版本控制工具；
- 软件维护工具中的配置管理和变更管理工具；
- 软件管理和支持工具中的配置管理工具。

### 6.2 Jira

Jira 主要属于：

- 软件管理和支持工具中的项目管理、任务管理工具；
- 软件维护工具中的缺陷跟踪工具；
- 也可以支持需求管理和测试管理。

### 6.3 Jenkins

Jenkins 主要属于：

- 软件开发工具中的持续集成和构建工具；
- 软件维护工具中的自动化发布和回归测试工具；
- 软件管理和支持工具中的发布管理和过程支持工具。

### 6.4 IDE

IDE，如 Visual Studio Code、IntelliJ IDEA，主要属于软件开发工具，但也支持软件维护、调试、重构、代码分析和版本控制。

## 七、记忆方法

> **开发工具负责“造软件”，维护工具负责“修软件”，管理和支持工具负责“管软件项目”。**

也可以简记为：

- 软件开发工具：**写出来**；
- 软件维护工具：**改得动**；
- 软件管理和支持工具：**管得好**。
